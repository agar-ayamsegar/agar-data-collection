Can two gas sensors smell a spoiling chicken?

Every checkpoint ever recorded for this project — 6 chickens, 31 runs, MQ‑137 and MQ‑135 — read straight off disk, cleaned, and checked. Short answer: both sensors smell it — only MQ-135 does so on a scale that transfers between chickens, and there is one confound you have to kill before any of it counts.

One JSON per checkpoint — one chicken at one hour. Each file holds two arrays of raw ADC counts (the baseline, box empty; then the sample, chicken inside) plus the hand-written sensory fields. Here is every field, its Python type, and how often it is usable.

03

Cleaning: what is broken

Nothing here gets edited on disk — these are the exclusions and fixes to apply when you build the model table.

Three things make a run unusable, not just noisy.
  • ADC railing — A01_h5 and A01_h6 hit 1023 on MQ‑135 at VREF 1.1. The true value is above the ceiling, so the magnitude is censored, not measured.
  • rel above 1.0 — A02_h2 (MQ‑135, 1.08) and A03_h4 (MQ‑137, 1.28) read less gas with the chicken in than with the box empty. Physically impossible: the baseline was contaminated.
  • weight_g is a placeholder on all 31 runs — fixed 2026-10-22. All 31 runs now carry a real gram weight: A01 at 2500 g, A02–A06 between 1017 g and 1158 g.
gap_jump was checked, and it is not a problem. 11 of the 26 usable runs have one. They track smell better than the runs without (ρ = −0.91 vs −0.80), and at matched smell levels they read the same: smell 1, 0.86 vs 0.87; smell 5, 0.17 vs 0.20. The chicken is already sealed in the box during the gap, so no gas is lost — only the clock starts late, and by 120 s the curve has flattened enough that it barely moves the number. It is no longer counted as a data-quality flag on this page.
The VREF split. A01 ran at VREF 1.1, everything after at 5.0. Raw counts are ~4.5× apart and must never be pooled — but rel divides the scaling out, so the 3 unsaturated A01 runs stay comparable. All model fitting below uses the 26 VREF 5.0 runs only, which is the conservative choice.

05

Correlation: which sensor carries the signal

Pearson r is the straight-line fit; Spearman ρ only asks whether the order matches, which suits smell_level (a 1–5 rank, not a measurement). When the two agree, the relationship is real and not one outlier dragging a line.

MQ-137 is not the weak sensor. It is the sensor that does not carry an absolute scale. Its response is as big as MQ-135's — median rel 0.68 against 0.60, and it bottoms out at 0.14. The low pooled correlation is not "it cannot smell", it is "0.65 means a different thing on A03 than it does on A05".

The test that separates "cannot sense" from "cannot compare"

Spearman ρ against hours computed inside each chicken, which cancels that chicken's own offset. Then the same question with every chicken rescaled by its own hour-1 reading.

So MQ-137 earns its place — as a relative sensor, not an absolute one. Inside a single chicken, relmin_137 ranks the checkpoints at ρ = −0.54 on average, and −0.66 to −0.90 on A04, A05 and A06. Rescaling by each chicken's hour-1 reading lifts it from −0.54 pooled to −0.71. MQ-135 barely moves under the same treatment (−0.85 → −0.84) because it did not need the help.
The one chicken that breaks the pattern is A02 (ρ = +0.4), and the log already says why: h3 came straight out of a closed container and h4 was fanned first. Two known handling errors, one chicken.
The physical reason. MQ-137 is tuned for ammonia, which only shows up late (smell 4–5, pesing), so across the 1–8 h window it spends most of its range on a gas that is not there yet and is more exposed to its own drift and warm-up state. MQ-135 answers to the whole VOC mix, and the apek/asem stage arrives early. Keep both: MQ-135 calls the hour, MQ-137 confirms the ammonia end — and if you ever log an hour-1 reference per chicken, MQ-137 becomes a second usable feature rather than a passenger.
06

The confound that can invalidate all of it

MQ-135 is a humidity-sensitive sensor. So before believing it smells spoilage, check what humidity did.

It is the room, not the chicken. Split each run's humidity into the box state before the chicken went in and the rise during the sample, and the two separate cleanly: the box starts at 35 % in the morning and 77 % at night (r = +0.91 with hours), while the chicken itself only adds +1 to +13 % (r = +0.64).
A05 and A06 ran in parallel on 21 Oct, same room, and their box humidity at matched clock times agrees to within 1–6 points — 39/35 % at lunch, 71/75 % at night. corr(box RH, clock time) = +0.97. Two independent chickens cannot drive one shared curve, so the driver is the evening room and a box that never dries out between checkpoints.
And the baseline does not cancel it. The baseline is taken in that same damp box seconds earlier, so it should divide out — but rel300_135 still tracks the box state at −0.76, more strongly than the chicken's own contribution at −0.58.
This does not mean the model is wrong — it means the dataset cannot prove it right. But it localises the problem to the room, which is fixable.
The experiment that settles it: run one chicken on a reversed clock. Buy it in the evening and take h1 at about 21:00, when the room is already at ~75 % RH.
  • If h1 still reads fresh (rel ≈ 0.85) in a humid room → humidity is not driving the signal, and everything above stands.
  • If h1 reads spoiled → the model has been reading the clock, not the meat.
This beats a wet-cloth control: it is a real chicken, it costs one ordinary run, and it breaks the age-versus-clock confound directly rather than only testing the sensor. Worth doing anyway, cheaply: a wet-cloth control, and drying the box properly between checkpoints — 2 min of airing plainly does not take it from 35 % back down at night. Temperature is a weaker second confound (r = −0.62 with smell), drifting 34→31 °C across the day.
07

Does one threshold actually work?

The practical question: can a single cut-off on one number call "stop eating this"? Target is smell_level ≥ 4 (pesing/rotten), which is the honest label — label itself is derived from the clock, so predicting it would just be re-predicting hours_since_buy.

In-sample fits the threshold on all runs then scores the same runs — always optimistic. Leave-one-chicken-out fits on five chickens and tests on the sixth, which is the number that survives contact with a new chicken.

Can both sensors vote together?

The obvious rule — require MQ-135 and MQ-137 to fire — buys nothing, because MQ-137's mistakes contain MQ-135's. What does work is feeding both into one number.

Two rules, not two sensors. The ratio rel300_137 / rel300_135 rises as the chicken spoils (MQ-135 falls faster than MQ-137), hits the same 96 % held-out — and gets a different run wrong. MQ-135 alone misses A02_h3; the ratio misses A04_h5. Two independent rules, so run both:
  • Both agree — 21 of 23 runs, and 21/21 correct.
  • They disagree — 2 of 23 (9 %), and they are exactly the two hard runs. That is the ULANGI SCAN case the product already has.
The ratio also needs no hour-1 reference — both rel values are already baseline-normalised inside the run — so unlike the h1 trick it survives into the handheld, where you scan a chicken once and have no history for it. And it is less humidity-tangled: r +0.70 against −0.80.
Caveat: 21/21 is 21 runs from 5 chickens with 2 disagreements. The thresholds were fitted leave-one-chicken-out, so the protocol is honest, but a 100 % on a sample this small is encouraging, not proven — and both rules still sit under the confound in section 06.
The 5-minute reading beats the 2-minute reading, and it is free. rel300_135 holds 96 % leave-one-chicken-out; rel120_135 — the current main feature in CLAUDE.md — holds 88 %. Same chickens, same sensor, same box: the only difference is waiting three more minutes before typing x. Only three runs — A03_h3, A04_h1, A04_h8 — stopped short of 300 s and cannot supply the better feature at all.
08

What to change tomorrow

  1. Let every sample run 5 minutes, not 2. Buys +8 points of held-out accuracy for three minutes of waiting, and it loses nothing — rel120 is still in there.
  2. Run one chicken on a reversed clock — bought in the evening, h1 at ~21:00 in a 75 % RH room. It is one ordinary run and it settles section 06, which otherwise leaves the whole model contestable.
  3. Always record an hour-1 checkpoint for every chicken. It is the reference that makes MQ-137 usable (ρ −0.54 → −0.71) and it costs one extra run. Three chickens already have one; make it the rule.
  4. Keep collecting past hour 8 and below hour 1. Smell 4–5 holds only 7 of the 26 usable runs, from 4 chickens, and nothing was ever recorded past hour 8. The threshold is being fitted on a thin edge.
  5. Keep MQ-137, and stop judging it on the pooled number. It senses as strongly as MQ-135; what it lacks is a scale that transfers between chickens. Judge it per chicken, or against that chicken's hour-1 reading — never as a standalone absolute threshold, where it is only 69 % held-out.
Honest summary of the state of the data. 31 checkpoints, 26 usable, 6 chickens. Both sensors respond to a spoiling chicken; one of them, MQ-135, does it on a scale that survives moving to a new chicken, and separates fresh from spoiled at 96 % held-out — a real result at this sample size. It is not yet a validated result, because humidity tracks age too closely to rule out, the spoiled class holds 7 runs, and every chicken but one came from the same supplier on consecutive days. Treat the number as a promising pilot, not a model.
